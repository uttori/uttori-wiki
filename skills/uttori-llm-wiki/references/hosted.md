# Hosted writes

Use this procedure for hosted Uttori instances that expose `getDocumentForEdit`, `previewDocumentChanges`, and `applyDocumentChanges` to your authenticated MCP connection. If those tools are unavailable, propose edits for the checkout. A local Uttori checkout is optional. Read the original from the user's private archive, compute its SHA-256 from the original bytes, and use the user-confirmed archive-relative path. If the original has no archive location yet, arrange that with the user before filing a source note. Send derived content and source metadata over MCP.

1. Read the index and log, then search existing topics and aliases. Read each candidate with `getDocumentForEdit` before drafting so its version represents the exact base you used. Use `null` only for a page that the tool reports as missing. Check for a completed ingest of the same source digest.
2. Prepare patches using the same [source-note and catalog conventions](sidecars.md). Pass `slug`, `expectedVersion`, and `content`. Add a `title` for new pages. Put the source note's `wikiKind` and `source`, or a topic's `wikiKind`, under `metadata`. The operator must include these keys in Uttori's `allowedDocumentKeys`. Leave the ingest log patch last. Review target links and citations against existing and proposed pages before requesting a preview.
3. Call `previewDocumentChanges` and show the before and after values or their diff. Apply its ID only after the user approves that preview. A conflict requires reading the new page versions and reviewing a fresh draft. Preserve the user's intervening edits.
4. Keep the preview ID and latest receipt. If apply reports pending work or the response is lost, reconnect as the same writer and retry that ID. A stale batch can finish history or indexing for its own saved pages while rejecting new writes. If the preview expires, the server restarts, or conflicts remain, use `getDocumentForEdit` and `getDocumentHistory` to reconcile the current state. Draft only the remaining edits for fresh approval. A new receipt covers that new preview. Verify search separately and report any unresolved history or index work to the operator. A log entry alone confirms page writes, while the apply receipt confirms indexing.
